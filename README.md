# 原型生成 Skill 使用说明

## 概述

本工作区内置 3 个原型相关 skill，覆盖从"文字确认"到"HTML 交付"的完整链路，分别适用于 0-1 新建项目和迭代项目。

## Skill 一览

| Skill | 用途 | 适用场景 | 输出 |
|-------|------|---------|------|
| `text-prototype-from-scratch` | 从零生成文字版原型，确认后转 HTML | 0-1 新项目，无现有页面 | `.md`（确认稿）→ `.html`（交付物） |
| `text-prototype-iteration` | 基于现有页面做增量变更，确认后转 HTML | 迭代项目，有现有页面 | `.md`（含变更对照）→ `.html`（交付物） |
| `html-prototype-creator` | 直接生成 HTML 原型 | 跳过文字确认，快速出 HTML | `.html` |

## 如何选择 Skill

```
用户需求
  │
  ├─ 从零新建页面（无现有页面参照）
  │   → text-prototype-from-scratch
  │
  ├─ 在现有页面上做修改（新增/修改/删除模块）
  │   → text-prototype-iteration
  │
  └─ 已有明确的结构描述/截图，直接要 HTML
      → html-prototype-creator
```

## 完整工作流程

### 0-1 项目流程（7步）

```
步骤1：分析输入
  │  提取页面名、功能点、平台
  ▼
步骤2：拟定页面草案
  │  判断单页/多页、跳转关系、页面类型
  ▼
步骤3：Reference 填充 ← 新增
  │  检查 reference/templates/ 是否有对应模板
  │  ├─ 有 → 直接复用
  │  └─ 没有 → 调用框架图prompt从截图生成 → 写入 templates/
  ▼
步骤4：审问确认（grill-with-docs，强制）
  │  确认8个维度：页面清单/平台/用途/跳转/组件/功能范围/粒度/遗漏
  ▼
步骤5：生成文字版 MD
  │  每页一个 .md，布局结构引用步骤3的模板
  ▼
步骤6：用户确认 MD ← 新增
  │  用户确认结构无误
  │  ├─ 确认 → 进入步骤7
  │  └─ 需修改 → 回到步骤5调整
  ▼
步骤7：生成 HTML 原型 ← 新增
  │  调用 html-prototype-creator，将确认的 MD 转为 HTML
  │  用 computer:// 链接交付
```

### 迭代项目流程（9步）

```
步骤1：分析变更需求
  │  提取：改哪个页面/改什么/改成什么样
  ▼
步骤2：基线确认
  │  检查 reference/baseline/ 是否有该页面快照
  │  ├─ 有 → 直接引用，进入步骤4
  │  └─ 没有 → 进入步骤3
  ▼
步骤3：基线生成 + Reference 填充 ← 新增
  │  3a. 检查 templates/ 是否有模板
  │      ├─ 有 → 直接复用
  │      └─ 没有 → 调用框架图prompt生成 → 写入 templates/
  │  3b. 调用 text-prototype-from-scratch 生成当前状态
  │      → 存入 baseline/<页面名>-v1.0.md
  │  3c. 向用户确认基线准确性
  ▼
步骤4：变更范围识别
  │  对照基线，逐模块标记 [新增]/[修改]/[删除]/[不变]
  ▼
步骤5：拟定变更草案
  │  仅对 [新增][修改] 展开详细描述
  ▼
步骤6：审问确认（grill-with-docs，强制）
  │  确认9个维度：基线/变更清单/变更类型/范围边界/变更细节/
  │              新增完整性/业务状态影响/粒度/删除影响
  ▼
步骤7：生成文字版 MD
  │  每页一个 .md，含6部分（含变更对照）
  ▼
步骤8：用户确认 MD ← 新增
  │  用户确认变更结构无误
  │  ├─ 确认 → 进入步骤9
  │  └─ 需修改 → 回到步骤7调整
  ▼
步骤9：生成 HTML + 更新基线 ← 新增
  │  9a. 调用 html-prototype-creator，将确认的 MD 转为 HTML
  │  9b. 将新版 MD 存入 baseline/，版本号递增
  │  用 computer:// 链接交付
```

## 输出文件说明

### 0-1 项目输出

| 文件类型 | 命名规则 | 用途 |
|---------|---------|------|
| MD 文件 | `平台-页面名.md`（如 `mobile-home-page.md`） | 确认稿，用户确认结构用 |
| HTML 文件 | `[页面名]原型.html`（如 `首页原型.html`） | 交付物，可浏览器打开 |
| 索引文件 | `index.md` | 多页面时的导航索引 |

### 迭代项目输出

| 文件类型 | 命名规则 | 用途 |
|---------|---------|------|
| MD 文件 | `平台-页面名-v<版本>.md`（如 `mobile-home-page-v1.1.md`） | 确认稿，含变更对照 |
| HTML 文件 | `[页面名]原型-v<版本>.html`（如 `首页原型-v1.1.html`） | 交付物 |
| 索引文件 | `index.md` | 多页面时的导航索引，含变更统计 |
| 基线文件 | `reference/baseline/<页面名>-v<版本>.md` | 项目页面状态快照，迭代参照基准 |

## Reference 目录结构

两个 skill 共享相同的 reference 组织方式（各自独立目录）：

```
.trae/skills/text-prototype-from-scratch/
└── reference/
    └── templates/              # 通用页面模板
        ├── _index.md           # 模板索引
        ├── home.md             # 首页模板（待填充）
        └── ...

.trae/skills/text-prototype-iteration/
└── reference/
    ├── templates/              # 通用页面模板
    │   ├── _index.md
    │   └── ...
    └── baseline/               # 项目基线（迭代专用）
        ├── _index.md           # 基线清单
        └── ...                 # 首次迭代时自动填充
```

### templates/（通用模板层）

存放成熟页面的布局骨架（ASCII 框线图），供两个 skill 复用。

**填充时机：** 步骤3（0-1项目）或步骤3a（迭代项目），当 templates/ 中没有对应页面类型的模板时，调用框架图提示词从截图生成。

**复用规则：** 模板已存在时直接复用，不重复生成。

### baseline/（项目基线层，仅迭代项目）

存放项目自己页面的当前状态快照，是迭代项目的参照基准。

**填充时机：** 步骤3b（迭代项目），当 baseline/ 中没有该页面的基线时，调用 `text-prototype-from-scratch` 生成。

**更新时机：** 步骤9b（迭代项目），每次迭代完成后将新版状态存为新基线，版本号递增。

## Skill 协作链路

```
用户输入（截图+需求）
    │
    ▼
┌──────────────────────────────────────┐
│ 框架图提示词（通用版）                 │
│ 作用：从截图生成 ASCII 框线图          │
│ 触发：reference/templates/ 为空       │
│ 产出：写入 reference/templates/       │
└────────────────┬─────────────────────┘
                 │ 模板就绪
                 ▼
┌──────────────────────────────────────┐
│ text-prototype-from-scratch          │
│ 或 text-prototype-iteration          │
│ 作用：生成文字版 MD（确认稿）          │
│ 产出：.md 文件                        │
│  迭代项目额外：reference/baseline/    │
└────────────────┬─────────────────────┘
                 │ 用户确认 MD
                 ▼
┌──────────────────────────────────────┐
│ html-prototype-creator               │
│ 作用：将确认的 MD 转为 HTML 原型      │
│ 触发：用户确认 MD 后自动调用          │
│ 产出：.html 文件（交付物）            │
└──────────────────────────────────────┘
```

## 框架图提示词（通用版）

框架图提示词是一个独立的 prompt，不是 skill，但在两个 skill 的步骤3中被调用。

**作用：** 将移动端页面截图抽象为 ASCII 框线框架图。

**调用方式：** 将截图和页面名称填入 prompt 的变量部分，执行后生成框线图。

**产出：** ASCII 框线图，写入 `reference/templates/<页面类型>.md`。

**文件位置：** `e:\求职实操\拼团复盘\框架图提示词-通用版.md`

## 两个 Skill 的核心差异

| 维度 | from-scratch | iteration |
|------|-------------|-----------|
| 场景 | 从零新建 | 在现有页面上变更 |
| 步骤数 | 7步 | 9步 |
| 页面结构 | 5部分 | 6部分（+变更对照） |
| 页面概览 | 七要素 | 九要素（+基线版本+变更摘要） |
| 组件描述 | 全部组件展开八字段 | 仅 [新增][修改] 展开 |
| 状态描述 | 全量描述 | 仅描述受变更影响部分 |
| 参照基准 | templates/（通用模板） | templates/ + baseline/（项目基线） |
| 审问维度 | 8个 | 9个（+删除影响确认） |
| MD 文件命名 | `平台-页面名.md` | `平台-页面名-v1.1.md` |
| 迭代闭环 | 无 | 步骤9b 更新基线 |

## 常见使用场景

### 场景1：全新项目，从零画首页

```
用户："帮我画一个电商App的首页原型，移动端的"
→ 触发 text-prototype-from-scratch
→ 步骤3：检查 templates/ 无首页模板，提示用户提供截图
→ 用户提供截图 → 调用框架图prompt生成框线图 → 写入 templates/home.md
→ 步骤4：审问确认页面清单
→ 步骤5：生成 mobile-home-page.md
→ 步骤6：用户确认 MD
→ 步骤7：生成 首页原型.html
```

### 场景2：迭代项目，修改现有首页

```
用户："首页的超值券包从3张券改成2张，合并成入会礼和月享券"
→ 触发 text-prototype-iteration
→ 步骤2：检查 baseline/ 无首页基线
→ 步骤3：检查 templates/ 有首页模板 → 生成基线 home-v1.0.md
→ 步骤4：对照基线标记 超值券包 [修改]
→ 步骤6：审问确认变更方案
→ 步骤7：生成 mobile-home-page-v1.1.md（含变更对照）
→ 步骤8：用户确认 MD
→ 步骤9：生成 首页原型-v1.1.html + 更新 baseline/home-v1.1.md
```

### 场景3：已有截图，直接要 HTML

```
用户："根据这个截图直接画一个HTML原型"
→ 触发 html-prototype-creator
→ 跳过文字确认，直接生成 HTML
```

## 最佳实践

1. **优先用文字版 skill**：结构层面的错误在 MD 阶段修改成本极低，到 HTML 阶段再改成本高
2. **首次使用时提供截图**：截图能让框架图prompt生成准确的布局模板，填充 reference
3. **Reference 会自动积累**：第一次使用时填充模板，后续复用，越用越快
4. **迭代项目必先建基线**：没有基线就无法做变更对照，步骤3会自动处理
5. **基线版本会自动递增**：每次迭代后步骤9b 自动更新，保留历史版本便于追溯
